# Zadání: Oprava n8n workflows pro DataTalk Event Notifications ## Kontext Máme 4 n8n workflows pro notifikační systém DataTalk events. Workflows jsou funkční, ale porušují n8n best practices a mají kritické bezpečnostní/stability problémy. ## Umístění souborů - `/Users/chocho/datamesh/datatalk-sync/workflows/01-subscriber-signup.json` - `/Users/chocho/datamesh/datatalk-sync/workflows/02-email-verify.json` - `/Users/chocho/datamesh/datatalk-sync/workflows/03-telegram-verify.json` - `/Users/chocho/datamesh/datatalk-sync/workflows/04-event-scraper.json` ## Cíl workflows (produkční požadavky) ### Workflow 1: Subscriber Signup **Účel**: Uživatel vyplní formulář s emailem a Telegram username, obdrží verifikační linky **Flow**: 1. Form Trigger zobrazí formulář (email + telegram username) 2. Vygeneruje 32-byte token (expires 24h) 3. Uloží do Data Table `subscribers` (email, telegram, token, token_expiry, *_verified=false, active=false) 4. Pošle verification email (SendGrid SMTP) 5. Pošle verification Telegram message 6. Vrátí success response **Produkční očekávání**: - Musí handlovat duplicate emails (vrátit chybu nebo update existing) - Musí validovat email format - Token musí být kryptograficky bezpečný - Pokud Telegram send selže, workflow pokračuje (email stačí) - Response timeout max 30s ### Workflow 2: Email Verification **Účel**: Uživatel klikne na link v emailu, označí email jako verified **Flow**: 1. Webhook GET `/datatalk-verify-email?token=XXX&email=YYY` 2. Najde subscriber v Data Table (email + token match) 3. Zkontroluje token expiry (< 24h) 4. Update `email_verified=true` 5. Pokud i `telegram_verified=true`, update `active=true` 6. Vrátí HTML response **Produkční očekávání**: - Musí handlovat expirované tokeny (vrátit 400) - Musí handlovat neexistující tokeny (vrátit 404) - Musí být idempotent (kliknutí 2x na stejný link = OK) - Response timeout max 10s ### Workflow 3: Telegram Verification **Účel**: Stejné jako Workflow 2, ale pro Telegram **Flow**: Identický jako Workflow 2, jen kontroluje `telegram` field místo `email` **Produkční očekávání**: Stejné jako Workflow 2 ### Workflow 4: Event Scraper **Účel**: Každý týden scrapuje kalendář DataTalk events, extrahuje info pomocí OpenAI, notifikuje aktivní subscribery **Flow**: 1. Schedule Trigger (pondělí 8:00, každý týden) 2. Fetch https://www.datatalk.cz/kalendar-akci/ (HTML) 3. Extract všechny event URLs (a[href*='/akce/']) 4. Pro každý URL (loop): a. Check if exists in Data Table `events` b. Pokud ne, fetch event page HTML c. Convert HTML to markdown d. OpenAI extraction (title, dates, location, venue, speakers, summary) e. Save do Data Table `events` f. Fetch active subscribers g. Pro každého: pošli email + Telegram notifikaci 5. Continue loop (další event) **Produkční očekávání**: - Musí handlovat OpenAI API errors (retry nebo skip) - Musí handlovat Telegram/Email send failures (continueOnFail) - Musí být idempotent (re-run = no duplicates) - Max execution time: 10 minut - OpenAI rate limit: max 10 req/min ## Kritické problémy k opravě ### 1. Code Nodes - require('crypto') nefunguje **Problém**: `require('crypto')` není dostupné v n8n Code nodes **Lokace**: `01-subscriber-signup.json` line 37 **Oprava**: ```javascript // ŠPATNĚ const crypto = require('crypto'); const token = crypto.randomBytes(32).toString('hex'); // SPRÁVNĚ (option 1 - crypto module v n8n) const token = $helpers.crypto.randomBytes(32).toString('hex'); // SPRÁVNĚ (option 2 - fallback) const token = Array.from({length: 64}, () => Math.floor(Math.random() * 16).toString(16) ).join(''); ``` ### 2. Missing Error Handling v Code Nodes **Problém**: JSON.parse, Date parsing bez try-catch **Lokace**: Všechny workflows **Oprava**: Obalit kritické operace v try-catch ### 3. HTTP Request - missing timeout & retry **Problém**: HTTP nodes nemají timeout ani retry logic **Lokace**: Všechny HTTP Request nodes **Oprava**: Přidat do options: ```json { "timeout": 30000, "retry": { "maxTries": 3, "waitBetweenTries": 1000 } } ``` ### 4. Telegram API - nesprávný chat_id format **Problém**: `"chat_id": "@username"` funguje jen pro public channels **Lokace**: `01-subscriber-signup.json` line 141, `04-event-scraper.json` line 338 **Oprava**: - Pro produkci: Potřebujeme numeric chat_id (získat přes bot conversation) - Pro MVP: Použít "@" prefix a informovat uživatele že musí mít public telegram ### 5. Chybějící credentials **Problém**: Workflows odkazují na credentials které neexistují **Lokace**: - `smtp` credential (SMTP) - `openai-auth` credential (OpenAI API) **Oprava**: - SMTP: Použít credential name "SMTP" (bude vytvořen ručně nebo via post-init) - OpenAI: Změnit na environment variable nebo vytvořit credential ### 6. OpenAI error handling **Problém**: Parse OpenAI Response má try-catch, ale error se stejně pokusí uložit do DB **Lokace**: `04-event-scraper.json` line 207 **Oprava**: Přidat IF node před Save Event: ``` Parse OpenAI Response → IF ({{ $json.error === undefined }}) → TRUE: Save Event → FALSE: Log Error (nebo skip) ``` ### 7. Notification failures **Problém**: Pokud email/telegram selže pro jednoho subscribera, celý workflow failne **Lokace**: `04-event-scraper.json` line 310+ **Oprava**: Nastavit `continueOnFail: true` na Send Email/Telegram nodes ### 8. Hardcoded magic values **Problém**: Token expiry, OpenAI model, content limits hardcoded **Lokace**: Všechny workflows **Doporučení** (ne kritické): - Token expiry: přesunout do env var nebo constant - OpenAI model: OK (gpt-4o-mini je reasonable default) - Content limit 8000: OK pro tento use case ## n8n Best Practices k dodržení 1. **Error Handling**: - Všechny Code nodes musí mít try-catch pro kritické operace - HTTP nodes musí mít timeout - Notification nodes musí mít `continueOnFail: true` 2. **Credentials**: - Používat named credentials (ne inline API keys) - Pro env vars: preferovat `$env.VAR_NAME` syntaxi 3. **Expressions**: - Používat `={{ }}` pro expressions - Používat `JSON.stringify()` pro JSON v expressions - Testovat null/undefined před přístupem k properties 4. **Data Tables**: - Používat `n8n-nodes-base.dataTable` (ne `n8nTables`) - Search before create (avoid duplicates) - Používat `limit: 1` pro single record search 5. **Webhooks**: - Vždy nastavit `webhookId` pro stability - Používat `responseMode: "responseNode"` s respondToWebhook 6. **Code Nodes**: - Preferovat `runOnceForAllItems` mode - Vracet `[{ json: {...} }]` format - NIKDY nepoužívat `require()` - použít `$helpers` nebo built-in APIs 7. **Loops**: - Používat Split in Batches pro processing velkých seznamů - Zajistit exit condition - Testovat s malým batch size (1-5 items) ## Acceptance Criteria (jak poznat že je to hotové) ✅ **Všechny workflows musí projít n8n validation** bez errors ✅ **Code nodes nesmí obsahovat `require()`** ✅ **Všechny HTTP nodes mají timeout** ✅ **OpenAI error se nepokusí uložit do DB** ✅ **Notification failures nezpůsobí fail celého workflow** ✅ **Telegram API používá správný formát** (nebo je dokumentované omezení) ✅ **Token generation je kryptograficky bezpečný** ✅ **Data Table operations mají error handling** ## Dodatečné poznámky - n8n verze: 2.4.8+ - Data Tables jsou beta feature (N8N_ENABLED_MODULES=data-table) - SendGrid SMTP již nakonfigurováno v docker-compose.yml - Environment vars dostupné: WEBHOOK_URL, TELEGRAM_BOT_TOKEN, SMTP_SENDER, OPENAI_API_KEY ## Výstup Opravi všechny 4 workflow soubory tak aby: 1. Dodržovaly n8n best practices 2. Měly proper error handling 3. Byly production-ready 4. Fungovaly podle produkčních očekávání výše Uprav JSON soubory přímo pomocí Edit/Write toolů.
